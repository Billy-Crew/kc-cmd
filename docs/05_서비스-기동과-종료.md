# 서비스 기동과 종료

서버는 여러 프로세스(pmr, kqp, recv2r 등)가 **서비스**(레이아웃) 단위로 묶여 동작합니다. 서비스 단위로 기동·종료하거나, 프로세스 하나씩 다룰 수 있습니다.

| 명령어 | 설명 |
|---|---|
| `kc service` | 서비스(레이아웃) 단위 기동·종료·조회 |
| `kc all-services` | `env.moon` 에 등록된 서비스 전체를 하나씩 기동·종료 |
| `kc run` | 프로세스 하나 기동 |
| `kc kill` | 프로세스 종료 |
| `kc lockclear` | 중복 실행 방지용 락 파일 삭제 |

## kc service

```bash
kc service [하위명령] [서비스명]
```

| 하위 명령 | 설명 |
|---|---|
| `kc service list` | 서비스 목록과 설명 |
| `kc service preview [서비스명]` | 기동될 프로세스 목록 미리 보기 (기동하지 않음) |
| `kc service start [서비스명]` (`up`) | 서비스를 구성하는 프로세스 기동. 이미 떠 있는 프로세스는 건너뜀 |
| `kc service stop [서비스명]` (`down`) | 서비스를 구성하는 프로세스 종료 |

```bash
kc service list
kc service start SERVICE_A
kc service start SERVICE_B
kc service stop SERVICE_B
```

서비스 이름은 서버마다 다릅니다. 위의 `SERVICE_A`, `SERVICE_B` 는 예시이며, 반드시 `kc service list` 로 이 서버의 서비스 이름을 확인하세요.

!!! note "NODE"
    서비스 이름 자리에 `NODE` 를 쓰면 `env.moon` 에 등록된 서비스 전체를 대상으로 합니다. 다만 `kc service start NODE` 로 기동하면 `recv2r` 가 인스턴스당 여러 개 기동되는 현상이 관측되어, 전체 기동에는 `kc all-services` 를 씁니다. (원인은 규명되지 않았습니다.)

## kc all-services

`env.moon` 의 `services` 에 있는 서비스(`kc service list` 에 나오는 것)를 하나씩 `up`/`down` 합니다.

```bash
kc all-services start    # = up
kc all-services stop     # = down
```

## kc run, kc kill

프로세스 하나를 **프로세스 코드**(`[애플리케이션].[인스턴스]`)로 지정합니다. 예를 들어 `pmr.p1` 은 애플리케이션 `pmr` 의 인스턴스 `p1` 입니다. 이 서버에 어떤 프로세스가 있는지는 `kc ps` 로 확인합니다.

```bash
kc run  pmr.p1      # 기동 (프롬프트에 YES 입력)
kc kill pmr.p1      # 종료 (프롬프트에 YES 입력)
kc kill pmr           # pmr 프로세스를 전부 종료 (서비스 그룹과 무관)
```

- `force` 를 붙이면 확인 없이 실행합니다.
- `kc kill [프로세스타입]` 은 같은 종류의 프로세스를 **모두** 종료하므로 주의하세요.
- 프로세스가 떠 있는지는 `kc ps` 로 확인합니다.

## kc lockclear

프로세스는 중복 실행을 막기 위해 락 파일(`/var/tmp/u_[애플리케이션].[인스턴스].pid`)을 만듭니다. 프로세스가 비정상 종료되어 락이 남았을 때 지웁니다.

```bash
kc lockclear pmr.p1
```
